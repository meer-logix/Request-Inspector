Security model

Debugging tools shouldn't create new leaks.

Request Inspector captures real request and response data — which means it has to be more careful with that data than the plugins it's inspecting. Here's exactly how that works.

Redaction happens in memory, before storage.

Sensitive values are matched and masked as the request is being captured — never after the fact. Nothing unredacted ever touches disk, the database, or a log file.

Pre-configured patterns cover the common leak points out of the box, and you can add your own regex rules for custom headers or fields specific to your stack.

Access is gated, not just hidden.

By default, Request Inspector requires the manage_options capability — the same bar as Settings. On top of that:

  • Optional IP/CIDR allowlist restricts who can even load the dashboard
  • A production safety switch keeps capture off unless WP_DEBUG is set or an admin explicitly opts in
  • An immutable audit log records every operator ID, IP address, and action with a UTC timestamp

The non-functional guarantees

Tracing overheadUnder 2.0ms per request (benchmarked around 1.82ms/req)
Storage quotaAutomatic background FIFO pruning via wp-cron; default cap 250 MB / 50,000 records
Redaction guaranteeCredentials sanitized in memory before any disk or database write
Browser supportChrome, Firefox, Safari, Edge — responsive down to 1280px
