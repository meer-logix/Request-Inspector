Installation

1

Download the plugin

Grab the latest .zip from the Download page or the WordPress.org plugin directory once published.

2

Upload it

In wp-admin, go to Plugins → Add New → Upload Plugin, choose the zip file, and click Install Now.

3

Activate

Click Activate. A new Request Inspector item appears in the wp-admin sidebar.

4

Turn recording on

Open Request Inspector → Settings → Recording & Retention and flip the master toggle. The status pill in the top bar turns green when it's live.

Prefer the command line? See the WP-CLI section below.

Getting started

With recording on, trigger any request against your site — load a page, hit a REST endpoint, or run a cron job — and it appears in the Request Explorer within seconds. Click a row to open the full inspector.

If the Explorer is empty, use the "Trigger Test REST Request" button on the empty-state screen, or "Load Sample Profiling Batch" to see the UI populated with representative demo data before your first real request comes in.

Configuration

Settings are split across four tabs:

  • Recording & Retention — sampling mode (100% / slow & errors only / adaptive 10%), capture scope per data type, retention window, storage cap, and per-component toggles.
  • Security & Redaction — sensitive key list, custom regex rules, IP allowlist, minimum capability, and the audit log.
  • Integrations — interop settings for environments that also run Query Monitor or WP-CLI tooling.
  • Advanced — high-detail backtrace capture toggle (adds tracing overhead; use on staging for deep dives).

Recording & retention defaults

SamplingSlow & errors only (recommended for production)
Retention window14 days
Storage cap250 MB / 50,000 records, FIFO pruned via wp-cron
Minimum capabilitymanage_options

WP-CLI

Basic WP-CLI commands for scripting and CI environments:

# purge all captured data wp request-inspector purge # export the last 50 slow requests as JSON wp request-inspector export --status=slow --limit=50 --format=json # toggle recording on/off from a deploy script wp request-inspector recording --on wp request-inspector recording --off

This plays well alongside Query Monitor — both can be active at once; Request Inspector's overhead guard keeps combined tracing under control.

Frequently asked questions

Does Request Inspector slow down my site?

No. Tracing overhead is benchmarked at roughly 1.82ms per request and capped under 2.0ms even at 100% capture. Most sites run "Slow & errors only" or "Adaptive 10%" sampling in production, which lowers it further.

Is it safe to run on a live production site?

Yes, with the defaults on. Sensitive values are redacted in memory before storage, access is gated behind manage_options, and you can layer on an IP allowlist and a WP_DEBUG-only safety switch.

How is this different from Query Monitor?

Query Monitor is strong at hook and query introspection but doesn't show the actual request or response body. Request Inspector adds a full request/response viewer, a DevTools-style waterfall, built-in redaction, and an IP allowlist with an audit log. See the full comparison.

What WordPress and PHP versions are supported?

WordPress 6.0+ and PHP 8.0–8.3, tested against MySQL 8.0.x. The dashboard supports Chrome, Firefox, Safari and Edge down to 1280px-wide viewports.

How much data does it store, and for how long?

Retention is configurable at 7, 14 or 30 days, capped at 250MB or 50,000 records by default. A background wp-cron job prunes older records on a FIFO basis.

Can I disable capture for specific plugins?

Yes — the Recording & Retention screen includes a per-plugin toggle table, so noisy plugins can be excluded from capture without turning tracing off entirely.

Is Request Inspector free?

Yes. It's released under the GPLv2 (or later) license — the same license WordPress core uses — and is free to install and self-host.
